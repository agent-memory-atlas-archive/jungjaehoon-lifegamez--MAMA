Owner agent · development memory · shared engine

Work that carries over. History you can return to.

MAMA runs one owner agent on Claude or Codex: it watches connected work, keeps task history and evidence, answers on Telegram, publishes reports and recalls corrections. Development memory gives Claude Code decisions and checkpoints. Both use mama-core, the shared engine for storage, revisions, evidence and search.

Who it is for

Owners following work. Developers carrying decisions.

Follow work across conversations and work tools, or retain decisions across coding sessions. Task history and similar-case search are the focus. Records and the embedding index stay local; model requests, configured connectors and native web tools can send content to external services. There is no hosted MAMA service. Team use comes after the owner checks pass on real data.

What carrying the work means.

How it works

Two start paths. One shared engine.

Part Purpose and data
MAMA OS · 0.57.0 One owner agent · Telegram · task history · reports · state in ~/.mama/
Development memory Plugin 2.0.1 + MCP 2.2.1 · decisions and checkpoints · ~/.claude/mama-memory.db
mama-core · 4.0.0 Storage · revisions · evidence links · memory · local search · runtime drivers

Collect and attach. Five connectors retain originals and changes: Chatwork, Slack, Trello, the Kagemusha read-only bridge and Google Calendar through gws. The agent updates tasks, wiki pages and daily journals from evidence.

Answer and report. Owner messages, source deltas and scheduled reports enter the owner runtime. Live changes become a notification or acknowledgement, followed by a board refresh. Full reports default to 08:00, 13:00 and 18:00 KST; hourly reminders run 09:00–21:00. Historical replay processes day windows through the same runtime.

Recall and verify. Relevant lessons, preferences and constraints reach the next turn. The viewer shows work, board, memory graph, wiki and logs. The agent judges; the host collects, stores, searches, executes and retains traces and delivery receipts. Package versions above are manifest versions, not a release of this rebuild.

Getting started

Build the unreleased rebuild/owner-flow checkout with Node.js 22.13+. 

pnpm install
pnpm build
node packages/standalone/dist/cli/index.js init
  • Owner setup: authenticate Claude or Codex, then run mama init in your terminal. Type tokens with echo off.
  • Development memory: install the Claude Code plugin or configure a stdio MCP client. No OS daemon is required.
  • Owner status: mama status reports running/stopped; 127.0.0.1:3847/health reports liveness.
  • Keep the two data homes separate. Confirm a real owner answer or a memory save-and-retrieve round trip; process status alone does not prove success.

Local plugin: /plugin marketplace add /path/to/MAMA, then /plugin install mama@mama-dev. Its manifest still launches the published MCP package; use the setup guide's local stdio configuration to test this branch's server. Published packages may lag the rebuild.

Security

Local access by default. Explicit credential boundaries.

  • The viewer binds to 127.0.0.1 by default; data routes are read-only.
  • Telegram accepts an allowed chat and owner sender. File delivery uses the configured owner destination.
  • The owner enters tokens in a terminal. auth.env is mode 0600 and outside the agent's readable files; both backends receive an environment without secret-shaped variables and keep writes inside the workspace.
  • External evidence is quoted as untrusted; recallable writes reject recognised secret shapes. These controls do not guarantee complete secret detection or injection immunity.
  • Security events are recorded, and suspicious request classes alert the owner on Telegram. Protect data homes and logs as private owner data.

Remote viewer access. Configure authentication before exposing owner data. The health route checks liveness, not answer quality or report delivery.

  1. Use MAMA_AUTH_TOKEN as a bearer credential, or a verified Cloudflare Access JWT.
  2. Configure the Access issuer and audience when using a tunnel. Tunnel headers alone never establish identity.
  3. Set the viewer Host allowlist; it applies to public routes too. Keep the origin on loopback when tunnelling.
  4. Keep OS state in ~/.mama/ separate from development memory in ~/.claude/mama-memory.db.
