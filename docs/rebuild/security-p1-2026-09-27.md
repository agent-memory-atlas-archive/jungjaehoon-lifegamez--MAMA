# Security P1 — owner credentials and viewer authentication

2026-09-27 · branch `rebuild/owner-flow` · no commit or daemon restart.
Owner checks: Answer and Report; source quoting also protects Recognise.

## Implemented

- Standalone supplies the daemon environment minus names matching
  `/(TOKEN|KEY|SECRET|PASSWORD|CREDENTIAL)/i`. No secret-shaped exception is required:
  CLI authentication uses backend homes; non-secret Claude messaging settings survive.
  Core's `processEnv` is a complete replacement, with no product-specific filtering in core.
  The parent backend and its native children share that environment; daemon connectors retain theirs.
- Claude receives absolute `Read` denies through `--disallowedTools`, alongside the existing
  `--allowedTools`; both workspace settings scopes get Bash `sandbox.filesystem.denyRead`.
  Targets: `auth.env`, `config.yaml`, `runtime/`, `.codex/` and any explicitly configured Codex home.
- Codex receives a named workspace permission profile with those paths set to `deny` and command
  network disabled. Both new and resumed threads select `permissions`, without a legacy `sandbox`
  override; profile paths participate in session compatibility. Shared-engine defaults are unchanged.
- Both model-result boundaries quote the six requested evidence actions and their errors. The outer
  JSON stays parseable; `data` contains delimited text (serialized JSON for structured source data).
  IDs and attachment paths inside that quoted data are unchanged; host receipts remain structured.
  Delta message text, previews, fallback payloads and replay queues are quoted and embedded closing
  markers are neutralized. Removed unused instruction and stripping helpers.
- Viewer authentication verifies RS256 signatures against issuer JWKS cached for ten minutes, plus
  issuer, audience, finite expiry, optional nbf/iat with 60-second skew and an email claim. Retrieval
  failures fail closed; fetch redirects are refused and latency is bounded. No assertion or fetch
  error details are logged. Any tunnel/Access header disables the local bypass, even an empty header.
  Only a verified assertion or `MAMA_AUTH_TOKEN` admits tunnel traffic. The old token alias is removed.
  Unset/invalid `MAMA_CF_ACCESS_ISSUER` or `MAMA_CF_ACCESS_AUD` disables JWT authentication and logs
  one value-free startup message. Direct loopback without tunnel headers remains available.
