# MAMA rebuild — carry, keep, drop

Status: draft for owner approval · 2026-09-25
Purpose: [INTENT.md](../../INTENT.md) v7. This file is a work list. It edits rows in place; it
does not grow dated sections.

## Why a new branch

`move-owner-work-to-commitments` is 522 commits ahead of main (4066dfb37, 2026-09-15). About
2–3% of them touched the owner flow. Progress was measured structurally (W1–W25, 22/25) while the
product tracker stayed at 0/53. The first real owner turn ran on day 8. Deletions removed policy
content the agent needed ("read the ledger first", "resolve the names", "save who did what",
"relate to earlier work"), and two days later both symptoms appeared. The engine it built works.
The product layer on top of it does not. We keep the engine and rebuild the product layer.

## Two goals

1. **MAMA's owner flow** (INTENT v7): Kagemusha's loop + a wiki + memory that carries over, with
   task history and similar-case search.
2. **mama-core as a shared engine.** A separate project such as nh connects to mama-core and
   writes and searches its own records: its own DB path, its own principals, its own sources.
   It never imports `standalone` and never touches `~/.mama`. Records, revisions, evidence links
   and search belong to the engine. Work vocabulary (task fields, roles, board, reports) belongs
   to each product.

## Base and shape

- New branch `rebuild/owner-flow` from **main 4066dfb37**, created in the project folder
  (`~/project/MAMA`). Before switching, check that the tree is clean and that no other session is
  working there.
- The daemon runs `packages/standalone/dist` from this folder and resolves core through the
  workspace. Switching to main, `pnpm install` and the core build (which wipes `mama-core/dist`)
  each break it. **W0 starts with `launchctl bootout`. The Telegram bot is dark until the W1
  cutover**, which is one more reason W1 has to land in days.
- Tag the old head `archive/unified-core-2026-09-25` (1725300eb). Nothing merges from it wholesale.
- **Pull, don't push:** a file comes over from the archive only when a work item below names it,
  together with its tests. A file that no item names stays in the archive.
- Main keeps its root tooling, CI and release scripts. Almost nothing in main's `standalone/src`
  survives, because main still has the layers the owner already retired (multi-agent, skills,
  envelope, tool-registry, gateway tool executor, discord/slack gateways). None of them come back.

## Done means

The owner asks these questions on Telegram, about real September data, and gets cited answers
that come out the same after a new session and after a restart:

1. "Who is working on what right now?"
2. "How did X progress, and what was the feedback?"
3. "Was there a similar case before? How did it go?"
4. The 08/13/18 reports and the board show the same state as the task ledger.
5. An owner correction changes the next relevant turn, leaves unrelated turns alone, and still
   applies after a restart.
6. A second consumer installs the **packed** mama-core tarball in a temporary directory, opens its
   own DB, then writes, revises, links and searches its own records through public exports only.

Tests, builds and receipts are supporting evidence only. A work item is done when its check passes:
for owner checks, on the installed daemon with `daemon.log` clean and the DB read back.

## Rules for this branch

- Progress is measured by checks passed, never by structural counts or status scripts.
- Relocate before delete. Removing policy text, a brief or a host step first names where its
  knowledge now reaches the agent, and one real owner turn confirms it.
- Core knows no consumer, and check 6 is the definition of that. A MAMA name inside core is a
  defect only when it makes the pack test fail. No vocabulary hunts beyond that.
- Docs budget: this plan stays under 200 lines. The check log gets 3–5 lines per item.
- Cutover (W1): only one daemon can poll the Telegram bot. Build standalone from this folder, then
  `launchctl bootstrap`. In `~/.mama/start.sh`, remove the exports for retired machinery
  (`MAMA_TRIGGER_LOOP*`, `MAMA_BOARD_RECONCILE`, `MAMA_RECONCILE_TASK_CONTEXT`,
  `MAMA_STAGE2_WORKORDERS`, `MAMA_TEMPORAL_RECONCILE`). Leave the credential lines alone and never
  print them.
