## Result and decisions

- Owner and native child tools reach the existing core effect-observation path and
  `tool_traces`. Read/web observations do not become replay-blocking effects.
  Factory/storage failures are observed without blocking execution. Traces retain
  tool name, masked input (at most 4,000 characters), status, duration and the
  **parent model run ID**; child identity remains in the summary. Native outputs
  are not copied. Codex observation IDs include the thread ID so identical provider
  IDs in different threads cannot merge or settle each other's rows.
- Trace input masking is shared with catalog receipts and viewer diagnostic text.
  Specific provider shapes, JWTs, named values, Basic/Bearer headers, CLI flags,
  URL credentials and quoted/escaped JSON secret fields are masked. Complete and
  truncated private-key blocks are removed. Ordinary content hashes remain valid;
  no entropy/length-only credential regex was added.
- The viewer rejects unapproved/malformed/duplicate Host values with 421 before
  authentication. `MAMA_VIEWER_HOSTNAMES` is the comma-separated extension to the
  loopback allowlist; the named reason is DNS rebinding. Existing public route
  semantics and verified Access JWT/bearer identity checks are preserved.
- Tunnel requests and failed authentication produce one bounded audit line, with
  path but no query, status, ray identifier, and verified identity hash or
  token/anonymous marker. Ordinary direct local requests remain silent.
- Wiki publish/update and report publish declare `recallableWrite`. The scanner
  now scans scalar leaves of the deepest permitted container, covering nested wiki
  evidence references while retaining the existing container-depth refusal.
  Refused writes do not change the visible page/report or leak into trace inputs.
- Both Claude stderr paths use the configured-secret redactor shared with Codex.
  Chunk boundaries and process shutdown retain partial secret matches until the
  stderr stream closes. Viewer internal failures, including wrapped action
  failures, return generic bodies and log bounded sanitized diagnostic details.
- The daemon creates/tightens the configured log to 0600 at boot. The viewer reads
  at most 256 KiB from its tail, returning at most 2,000 lines. `total` is `null`
  when the full-file line count is unknown; the viewer does not consume that field.
- Telegram's existing rejection policy is unchanged; rejected senders, including
  bots, now produce only hashed chat/sender identifiers. Shared connector downloads
  enforce 50 MiB in headers and streams, cancel failures, remove partial files and
  preserve existing targets. Telegram retains its narrower 20 MiB download cap.
  Slack sends its credential only to the approved HTTPS file origin and refuses
  automatic redirects.
- The security guide was rewritten around the implemented owner boundary, origin
  JWT verification, recallable-write scan, observation and explicit limitations.
  The owner account and deployment Access policy remain trust boundaries.
